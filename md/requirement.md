# `md/YAPSS/*.md` 編集方針

`lean/YAPSS/*.lean` の形式証明に 1 対 1 で対応する、**人間が読むための証明本文**を
`md/YAPSS/*.md` に書く。Markdown + MathJax。言語は日本語。

---

## 1. 何を書くか

### 1.1 要約を書かない

**これは証明である。要約・概説・「〜が示せる」の羅列にしてはならない。**
Lean 側に存在する命題は、対応する `md` に**命題と証明の両方**を書く。
証明の各段は、読者がその段の正しさを自分で検証できるだけの根拠を伴うこと。

### 1.2 帰納法は帰納法として書く

帰納法を使う箇所は、次の 3 つを**明示的に**書く。

1. **帰納法の対象**（何に関する帰納法か。自然数か、リストの長さか、項の構造か、
   `ST_PS` の導出か、整礎関係に関する整礎帰納か）
2. **基底段**（対象が最小の場合の証明）
3. **帰納段**（**帰納法の仮定**を明示的に述語として書き、それを用いた証明）

「帰納法により従う」「同様にして」で済ませてはならない。

### 1.3 自然言語の未定義語を使わない

証明本文で使ってよい自然言語は、**このリポジトリで定義済みの語**と、
**数学の標準語彙**（「したがって」「矛盾」「場合分け」「一意」など）に限る。

- ❌ 「この集合は展開について**閉じる**」
- ⭕️ 「$X$ について $\forall M \in X,\ \forall n \ge 1,\ M[n] \in X$ が成り立つ」

意味が一意に定まらない語を使いそうになったら、**その場で数式に書き換える**。
「ほぼ」「概ね」「うまく」「自然に」「明らかに」も同様に禁止。

## 2. 命題・定義のラベルと引用

### 2.1 ラベル

| 種別 | 書式 | 例 |
|---|---|---|
| 定理・補題 | `定理 <内容の名前> (T.<Lean識別子>)` | `定理 基本列の共終性 (T.pss_cofinality_holds)` |
| 定義 | `定義 <内容の名前> (D.<Lean識別子>)` | `定義 標準形 (D.ST_PS)` |

`<Lean識別子>` は `lean/YAPSS/*.lean` 中の宣言名をそのまま用いる
（`pss_cofinality_holds`, `ST_PS` など）。名前空間 `YAPSS.` は付けない。

見出しと**明示アンカー**を対で置く。アンカー名は `t-<Lean識別子>` / `d-<Lean識別子>`
（識別子はそのまま。大文字小文字も変えない）。

```markdown
<a id="t-pss_cofinality_holds"></a>
### 定理 基本列の共終性 (T.pss_cofinality_holds)
```

### 2.2 引用

命題を使うときは**必ず**ラベルで引用し、ハイパーリンクを張る。

- 同一ファイル内 : `[(T.pss_cofinality_holds)](#t-pss_cofinality_holds) より`
- 他ファイル     : `[(T.W_membership)](Wset.md#t-W_membership) より`

「先の補題より」「上で示したように」のような**リンクの無い参照は禁止**。

### 2.3 他ファイルで定義された記号

あるファイルに、他ファイルで定義された記号（例 $OT_B$、`ST_PS`、`olt`）が現れたら、
**そのファイル内での初出箇所**から定義へハイパーリンクを張る。

- 初出時に定義を再掲する必要はない。**リンクを張るだけでよい。**
- 2 回目以降はリンク不要（初出の 1 箇所のみ）。

## 3. ファイル構成と順序

### 3.1 対応関係

`lean/YAPSS/Foo.lean` ↔ `md/YAPSS/Foo.md`。

Lean 側のファイルが大きい場合は**分割してよい**（例 `Nrmstep`）。分割したときは
`lean` 側も同じ単位に分割し、対応を 1 対 1 に保つ。

### 3.2 記述順序は「基盤 → 結論」

読者が**未定義の記号に出会わない**よう、依存関係の下位から上位へ書く。
これにより引用リンクは常に「既出の定義・命題へ戻る」向きになり、循環が生じない。

停止性証明の依存順（下位が先）:

```
Def → Mechanized → Psi → Proofs → Wf → Wfsum → Otembed → Gterm0Olt
    → Seqlex → Nrm → Nrmstep → Cofinality → AscArg → Wset → Wtt
    → OrdinalFree → Final
```

`md/YAPSS/README.md` にこの順で目次を置く。

### 3.3 対象外

**停止性証明に使われない命題・ファイルは扱わない。**
そのようなものは `lean` 側からも削除する（履歴には残るので復旧可能）。
`md` も作らない。

---

## 4. 数式の書き方

- MathJax（`$...$` / `$$...$$`）。
- Lean の記法と数学記法が異なる場合、**md では数学記法**を用い、初出で対応を示す。
  例: `M⟦n⟧` は $M[n]$、`olt` は $\prec$、`sle` は $\preceq_{\mathrm{lex}}$。
- 対応表は各ファイル冒頭の「記法」節に置く。
- 列・リストは添字で書く。$M = (M_0,\dots,M_{X-1})$、$X = \mathrm{Lng}\,M$。

## 5. 検証

- md に書いた命題は、対応する Lean の宣言と**同じ主張**でなければならない。
  仮定を落とす・強める書き換えをしない。
- 証明の各段が Lean 側の証明と対応することを確認する。
  Lean 側で `omega` / `simp` に任せた計算は、md では**その計算を式で書く**
  （「`omega` による」と書かない）。
